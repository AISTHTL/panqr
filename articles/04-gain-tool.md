# GitHub 上这个开源工具，我拿它搭了一套获客系统

> 从「刷不完的讨论」到「37 个真在聊需求的人」，中间差的不是工具，是判断。

我做这套东西的起点特别朴素：**我想知道，某个行业里的人到底在聊什么，但靠刷是刷不完的。**

一个关键词底下几千条讨论，翻十分钟就审美疲劳了。而且你不知道哪几条是真用户说的，哪几条是水军复制粘贴的。

所以我用 WorkBuddy，加上 GitHub 上一个开源工具，搭了一套流程。它做三件事：把公开讨论整理成结构化数据 → 筛掉水军和广告号 → 剩下的拿来判断需求、找选题、拆爆款。

![开场](https://yulianyanxi.top/assets/up/1793085682097_g01_hook.jpg)

---

## 一、先把「大家在说什么」变成数据

第一步是在本地把开源工具跑起来。这一步的意义在于：数据落在自己电脑上，不经过任何第三方。

配置很简单，就三个框：**选平台、输一个行业关键词、勾上你要的信息**。

![配置面板](https://yulianyanxi.top/assets/up/1793085682740_g03_config_c.jpg)

比如我想看驾培这个行业，就输「考驾照」；勾选里我一般会选**评论和子评论**——子评论就是主楼下面那些回复，那里才是真人在接话的地方。

![选平台 关键词 勾评论 出JSON](https://yulianyanxi.top/assets/up/1793085682435_g02_screen_b.jpg)

跑完之后，它把这些内容输出成 JSON 文件。到这一步，**原本散落在页面里的讨论，变成了一份能筛选、能排序、能统计的数据**。

---

## 二、数据是脏的，这一步最容易被忽略

很多人做到这里就结束了，然后拿着几千条数据去群发——这是最没效率的做法。

真实情况是：一份原始结果里，**大半是水军、广告号和无关闲聊**。我那次的样本是这样的：

![128 到 37](https://yulianyanxi.top/assets/up/1793085683078_g07b_anim_filter_end.jpg)

**原始 128 条，筛掉 91 条，剩下 37 条。**

也就是说，如果你不筛，你八成以上的精力会花在跟机器人对话上。

---

## 三、让 Agent 按两个标准过一遍

筛选这一步我不用规则，用 Agent。因为我给的两个标准，本质上是判断题，不是关键词匹配能解决的：

**第一，他是不是真的在聊这个行业？**
**第二，他有没有说出来一个真实的需求？**

拿着这两条，让 Agent 逐条读、逐条判。清掉机器号和广告号之后，剩下的每一条，背后都是一个带着具体问题的人。

这一步的价值不在于「筛掉了多少」，而在于——**你终于知道这个行业里，大家反复在问的是哪几个问题**。选题、产品、话术，全都从这里来。

---

## 四、反向用法：拆开一条爆款

上面是「从一片讨论里找需求」，还有一个相反的方向：**你刷到一条爆款，想知道它为什么火。**

做法是给 Agent 一条视频链接。它能直接把原视频下下来——注意是原视频，不是录屏。

![粘贴链接解析](https://yulianyanxi.top/assets/up/1793085733101_g08_anim_download.jpg)

下完之后，它会把这条视频拆成三条轨道：**音频、字幕、画面**。

![拆成三条轨道](https://yulianyanxi.top/assets/up/1793085683748_g09b_anim_split_end.jpg)

拆开之后，你能看到的是：开头第几秒给钩子、口播的信息密度怎么排、画面在哪个位置换、字幕一屏几个字。

这些是「看得见的方法」。看懂了，就能照着做一遍——比看一百条「爆款公式」有用。

---

## 五、这套东西真正的分工

讲到这里，我想说一句我认为最重要的话：

> **工具负责搬，Agent 负责想。**

开源工具干的是体力活：把页面上的东西搬成数据、把视频拆成轨道。这些事它做得又快又准，但它不会判断。

判断是 Agent 干的：这条是不是真人、这句话里有没有需求、这个开头为什么留人。这些没法写成规则，只能交给会思考的那一层。

把这两层分开，整套流程才跑得动。很多东西做不起来，不是工具不够强，是**把判断也交给了工具**。

## 最后说清一件事

这套东西我全程用在**公开内容的整理和分析**上：看大家在聊什么、判断需求在哪、拆解一条爆款的构成。工具本身是 GitHub 上的开源项目，官方声明仅供学习和研究使用。

所以我在做的，是**把自己的信息处理流程自动化**，不是替谁去拿别人的东西。这个边界我一直守着，也希望你守。
